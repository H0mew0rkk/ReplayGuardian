- 检查了导入表：仅依赖 Windows 系统 DLL，没有 VC Redistributable DLL、Rust 运行时、WebView 或外部 GUI 框架要求。

## 资源测量

测量使用发布版、自动模式实际连接 MCP、`--safe --background`，不打开设置，不修改即时回放。启动后先等待五秒，再采样十分钟。测量脚本及数据随源码提供；未调用工作集清理或类似 API。

早期版本创建全部设置控件时约 18 MiB；按需创建后初测约 14.7 MiB，仍超过 10 MB 目标。最终十分钟数据由 `validation/performance.json` 与 `validation/performance-samples.csv` 记录。

最终发布版连续采样 600.503 秒，结果如下：

| 指标 | 实测 |
| --- | --- |
| EXE | 479,232 字节（468 KiB） |
| 工作集 | 14.73–15.49 MiB |
| 最大私有内存 | 2.95 MiB |
| 进程 CPU 时间增量 | 0.21875 秒 |
| 平均 CPU（整机） | 0.003036% |
| 平均 CPU（相对单核） | 0.036428% |
| 句柄（首/末） | 230 / 235 |
| 线程（首/末） | 10 / 6 |

工作集目标未达到；私有内存低于 10 MB 不代表工作集达标。十分钟内没有观察到句柄或线程持续递增，但这不能代替长期泄漏检查。CPU 平均值接近零。数据中的 SHA-256 与交付 EXE 一致。

测量口径：工作集包括共享系统库驻留页；私有内存另列。CPU 按进程 CPU 时间增量除以实际采样时长计算，同时给出相对单核和全机的百分比。NVIDIA App 自身常驻进程不计入本进程；本次使用 HTTP，没有启动官方桥接子进程。

## 尚未完整验证

- 注册表只做了本机快照对照，尚未完成用户参与的“开启→关闭→开启”校验，以及 DRM 关闭、Overlay 退出、驱动更新后的稳定性验证。默认注册表校验记录为空，不能自动发送快捷键。
- 自动回退顺序已由模拟逻辑测试覆盖，但未通过反复启停用户的 NVIDIA 服务做完整故障注入。
- 旧协议 2025-11-25、HTTP 不可用时的官方 stdio 桥接分支已经实现，尚无本机真实旧版服务验证。
- SendInput 按键发送、受保护内容退出后的自动恢复、输入权限受限和锁屏场景仍需真实交互验证；本次没有发送切换快捷键。
- 自启开关的实际登录验证、成功通知展示、Explorer 重启、多显示器 DPI、睡眠唤醒和另一台 Windows 10/11 机器的兼容性仍待验证。本机旧系统产品名不能作为已测试 Windows 10 的证据。
- 窗口创建及生命周期已自动化验证，电脑控制工具能列出正确窗口标题，但截图/鼠标交互检查遇到权限等待超时，尚未完成视觉检查。
- 设置打开后的资源占用、注册表模式和 stdio 模式的资源占用尚未分别长测；不把当前 MCP 后台结果推广到这些模式。

这些限制不会被解释为关闭状态，也不会触发管理员提权或修改 NVIDIA 内部状态。
