# Replay Guardian：可行性与开发计划

核实日期：2026-10-29。本文是实施前的设计，尚未生成程序或执行恢复操作。

后续实现和测试已进行。本文保留实施前的环境快照，实际结果请以 [验证记录](VALIDATION.md) 为准。

## 1. 结论

可以使用 Rust 和 Windows 原生 API 实现。推荐优先使用 NVIDIA 官方 MCP 读取状态和明确指定开启，注册表作为经过本机校验的兼容方案。

不能承诺注册表方法适用于所有 NVIDIA App 版本，也不能保证“先读状态、再发送切换快捷键”完全没有竞争风险。遇到不确定状态时停止恢复，比猜测关闭更重要。10 MB 常驻工作集是测量目标，当前没有程序，不能给出达标结论。

## 2. 已完成的核实

### 官方 MCP

- NVIDIA 官方文档要求 NVIDIA App 11.0.9.5xx 或以上，启用 MCP 访问，并使 In-Game Overlay 处于就绪状态。
- 支持本机 Streamable HTTP，也提供 NVIDIA 安装目录内的 stdio 桥接程序；桥接不会自行启用 MCP 服务。
- 默认地址是 `http://127.0.0.1:13508/mcp`。端口可能变化，优先使用新读取的 `%LOCALAPPDATA%\NVIDIA Corporation\NvAppMcpServer\server.json` 中的地址；文件缺失时可探测默认地址，不扫描大量端口。
- 只接受本机回环地址，禁用代理和远程重定向。设置连接、读取及整个请求的超时与响应大小上限。
- 状态工具：`nvapp_overlay_get_status`，参数 `{}`；只接受结果中有效的 Boolean 字段 `instantReplayEnabled`。字段缺失、类型错误、工具错误均为未知。
- 恢复工具：`nvapp_overlay_capture`，参数 `{"action":"toggle_instant_replay","enable":true}`。工具名称包含 toggle，但参数可指定目标状态；不省略 `enable`。
- 启动时及服务重连后核对实际 `tools/list` 的工具和参数，不能仅按版本号认定可用。
- 官方资料描述现代协议 `2026-07-28` 和旧协议 `2025-11-25` 等。现代协议没有 initialize 握手或协议会话，使用每次请求的版本、客户端元数据和相应请求头；旧协议才使用 initialize 及服务端返回的会话标识。两个流程必须分开。
- HTTP 响应可能是 JSON 或 SSE，需要同时支持。现代协议先只读发现服务；旧协议仅在确认不兼容现代协议时采用。
- 操作结果可能只有文本，不能把返回 200、发送成功或自然语言成功消息当作状态确认。

本机只读验证结果：

| 检查 | 实际结果 |
| --- | --- |
| NVIDIA 安装文件版本 | `NvAppApi.dll` 为 `11.0.9.565` |
| MCP 桥接程序 | 安装目录中存在 `NvAppMcpServer.exe` |
| 默认发现文件 | 本次检查未找到 |
| 默认 HTTP 端口 | 可以连接 |
| `server/discover` | HTTP 200，仅声明支持 `2026-07-28`，服务版本 `1.0.0` |
| `tools/list` | 包含上述状态和恢复工具；恢复参数支持 action 和 enable |
| 恢复工具注解 | `idempotentHint: false`，不能视为可无条件重复执行 |
| 状态读取 | SSE 响应，`structuredContent.instantReplayEnabled` 为 `false` |

这些检查没有调用恢复工具，没有发送快捷键，也没有更改 NVIDIA 设置。已证实状态读取可行，实际恢复效果仍待实现后的受控测试。

### 注册表

候选路径：`HKCU\Software\NVIDIA Corporation\Global\ShadowPlay\NVSPCAPS`。

社区实现使用候选值 `{1B1D3DAA-601D-49E5-8508-81736CA28C6D}`，类型为四字节 `REG_BINARY`，约定 `01 00 00 00` 开启，`00 00 00 00` 关闭。这是待验证的内部实现细节，不是 NVIDIA 承诺的公开接口。

本机只读快照中，候选值为 `00 00 00 00`，与 MCP 的关闭结果一致；`DwmDvrEnabledV1`、`IsShadowPlayEnabled`、`RecEnabled` 都为 `01 00 00 00`，所以不能用这三个值代替运行状态。

一个关闭快照不足以确认可靠性。实际启用注册表恢复前，需要由用户手动进行开启→关闭→开启，并对照 NVIDIA Overlay 或 MCP 记录候选值变化；还要测试 NVIDIA 进程退出后是否残留旧值，以及受保护内容触发关闭的情况。类型或数据不符合预期时返回未知。

校验结果绑定当前用户、路径、值名和 NVIDIA App 版本；版本变化后失效。可以通过设置中的可用性测试完成分步校验，不自动替用户切换回放。未校验时仍可查看原始诊断，但不能据此自动发送快捷键。

`RegNotifyChangeKeyValue` 只说明键发生变化，不能提高状态值本身的可信度。订阅使用只读查询和通知权限；每次通知后重新订阅、再读取状态，防止读取期间漏掉变化。处理键删除、重建、监听失效和句柄关闭；失败时自动模式尝试只读轮询。显式事件模式保留错误并定时重建监听。

## 3. 方案选择

| 方案 | 优点 | 代价与限制 |
| --- | --- | --- |
| 官方 MCP 优先，注册表经校验后兼容（推荐） | 有明确状态字段和目标开启参数；兼顾旧环境 | 需处理协议差异、SSE 和注册表校验 |
| 只支持官方 MCP | 最少状态歧义，代码较少 | 不能覆盖关闭 MCP 或较旧 NVIDIA App 的环境，不满足四种模式要求 |
| 只读注册表并发送快捷键 | 传输实现较少 | 内部值可能变化或残留，切换存在风险，不能作为默认可靠方案 |

推荐第一种，保持一个程序、一个设置窗口，不增加服务、插件或 Web 界面。

## 4. 最小架构和依赖

- 主线程负责原生窗口、托盘和消息循环；关闭设置窗口只隐藏窗口。
- 一个工作线程串行管理检测、恢复和验证。通过 Windows 事件、注册表通知和等待超时休眠，不使用忙循环。网络读取有界，暂停/退出可取消等待；退出时回收线程、网络连接及所有句柄。
- HTTP 优先使用 Windows WinHTTP；HTTP 不可用时按需使用已安装的 NVIDIA 官方 stdio 桥接，并管理其超时、管道及退出。不另外引入 HTTP 服务或常驻辅助程序。
- Rust 直接依赖计划为 `windows-sys`、`serde`、`serde_json`。配置和 MCP 共用 JSON 解析；不引入 Tokio、WebView、GUI 框架或第三方托盘框架。具体版本在实施时确认并提交 Cargo.lock。
- 初版交付 Windows x64 MSVC 构建，使用静态 CRT；系统 Win32 DLL 仍由 Windows 提供，无需用户另装 Rust 或 VC 运行时。

## 5. 检测和恢复行为

### 四种检测模式

- 默认自动：MCP → 已校验的注册表事件 → 已校验的注册表轮询；都不可靠时显示未知及原因。显示用户选择与当前实际方式。
- 单次超时先显示未知，不立刻跳方式。建议连续三次可用性失败后降级，降级后至少五分钟才后台探测高优先级方式；恢复期间不切换方式。永久错误可立即进入对应不可用状态。
- 显式 MCP / 轮询 / 事件模式不静默换成别的检测方式；显示错误和后续重试状态。
- 轮询默认十秒，可选 5 / 10 / 30 / 60 秒。事件模式按通知重读，同时保留恢复、重新连接和低频健康检查定时任务。
- 模式或配置改变会使旧检测和待确认结果失效，避免旧结果触发新配置下的恢复。

### 恢复安全规则

1. 只有未暂停、自动恢复开启且读取到可信的 Off 才进入恢复候选；On 和 Unknown 都不会发起开启。
2. 优先请求 MCP 明确开启。权限拒绝、受保护内容限制或不可重试错误不通过快捷键绕过。MCP 不可用时，才考虑已校验注册表配合 SendInput。
3. 快捷键前要求间隔采样仍为 Off，发送前再次读取，并确认 NVIDIA Overlay 仍在运行；用户正按住修饰键、桌面锁定、会话切换等情况推迟操作。不能确认状态时放弃发送。
4. 每次恢复只允许一个在途操作，随后进入验证窗口。计划在约 2 / 5 / 10 秒读取状态；窗口内不重复调用开启或发送快捷键。
5. 只有主动发起过恢复，且在同一操作的确认窗口内从可信来源重新读到 On，才记为恢复成功。仅检测到原本已开启不会通知；无法绝对判定同时发生的用户手动操作的因果关系。
6. 已确认仍关闭时按重试基础间隔退避，快捷键至少间隔三十秒，逐步增至五分钟。未知时只重试读取；发送结果不明确时禁止立即换方式补发。若验证窗口结束仍没有可信状态，显示未知并抑制后续快捷键，直至重新建立可信状态并经过冷却。
7. 不自动修改 NVIDIA 注册表、权限级别、Desktop Capture、DRM 或受保护内容设置。接口没有提供通用的 DRM 解除信号，不能声称准确识别所有限制；失败时等待和退避，状态不可判定时停止恢复。
8. 当前接口无法区分用户主动关闭与意外关闭。监控启用时会尝试恢复所有可信的关闭状态；用户想保持关闭时应先暂停监控或关闭自动恢复，界面和 README 明示这一点。

快捷键默认 Alt+Shift+F10，可配置修饰键和主键；必须与 NVIDIA Overlay 配置一致。SendInput 返回成功只说明输入被接收，不能证明回放已开启；受 Windows 输入权限限制时不会申请管理员权限。

## 6. 托盘、设置与配置

- 托盘菜单：状态、实际检测方式、暂停/恢复、设置、退出；处理 Explorer 重启后重建图标。
- 原生设置窗口：四种模式、检测/重试基础间隔、自动恢复、自启、成功通知、快捷键及可用性测试；使用系统字体、标准控件和 DPI 缩放，不增加视觉框架。
- 可用性测试分开报告连接、状态可读、恢复工具可用、注册表是否校验、监听是否成功；测试本身不调用恢复操作。
- 成功通知默认关闭。启用后仅满足上述恢复确认条件时通过系统托盘通知 API 请求显示，避免引入打包身份或额外进程。Windows 的通知设置可能抑制实际展示。
- 配置放在 `%LOCALAPPDATA%\ReplayGuardian\config.json`，有效修改自动保存，使用临时文件替换，损坏配置不静默启用危险行为。自动恢复默认开启；自启和通知默认关闭。
- 开机启动只修改当前用户 Run 项，保存带引号的 EXE 路径，不需要管理员权限。自启设置失败明确提示，不把保存配置当作自启成功。
- 当前用户会话内命名互斥体防重复运行。默认不记录每次检测；故障日志去重且限制大小，不记录令牌或屏幕内容。

## 7. 开发顺序与验收

1. **准备构建环境和核心逻辑**：准备 Rust MSVC 工具链；实现三态结果、配置、可注入时钟的恢复逻辑和模拟后端。
2. **实现最小监控**：优先接通已验证的本机现代 MCP，支持 JSON/SSE、错误及超时；加入旧协议兼容与按需 stdio 桥接。先验证读取，再在受控情况下验证明确开启。
3. **加入注册表兼容**：只读访问、分步校验、事件重订阅、键重建、轮询与自动降级；加入保守的 SendInput 备用恢复及退避。
4. **完成原生交互**：托盘、设置、通知、当前用户自启、单实例、自动保存和退出清理。
5. **自动化与真实验证**：完成下列测试矩阵，编译 release，记录实际结果和未覆盖内容，交付源码、构建说明、使用说明及条件允许时的 EXE。
6. **测量和精简**：启用优化体积、LTO、单代码生成单元、去除符号和 release panic abort；测量优化前后，避免用强制清理工作集伪造低内存。

必要自动化测试：

- 缺字段、null、错误类型、损坏 JSON、工具 isError、连接中断和状态超时均得到 Unknown，不触发恢复。
- 现代元数据与旧会话协议分离；JSON/SSE 分块、请求 ID 匹配、错误响应和会话失效正确处理。
- 已开启不操作；关闭才恢复；成功后独立重读；失败不通知；启动和重复检测不通知。
- 恢复窗口、事件风暴、慢响应和模式切换不会产生重复输入；暂停和退出使待处理恢复失效。
- MCP 连续失败后按顺序降级；未校验注册表不能进入自动恢复；高优先级探测具有冷却。
- 注册表未知编码、键删除、重建、监听失败及无后续事件时的重试均正确处理。
- SendInput 部分或完全失败不会被视为恢复成功；按键释放和冷却可验证。

真实环境仍需验证：

- 手动开/关与 MCP、注册表的一致性；受保护内容退出后的恢复、NVIDIA/驱动升级、Overlay 退出重启和机器睡眠唤醒。
- 快捷键与实际 NVIDIA 设置一致，输入权限受限时的行为。
- Windows 10/11 托盘、DPI、自启、Explorer 重启、通知和进程退出；当前机器只能证明本机覆盖，不能代替两个系统的完整测试。
- 记录 EXE 字节数；启动并稳定后分别测设置关闭、设置打开、MCP 和注册表模式的工作集/私有内存；闲置采样至少十分钟，使用进程 CPU 时间差计算平均占用，记录句柄和线程是否持续增长。NVIDIA 桥接进程如被使用，单独列出占用。
- 10 MB 为设置关闭时优先目标；若实际超标，报告真实值与主要原因，不填估计值或声称已达标。
