# 0.1.2：关闭窗口后无法重新打开的修复

## 原因与影响

标题栏关闭操作会先进入 Windows 的默认系统消息处理，再同步发送关闭消息。旧代码在调用默认处理时仍持有界面状态的可变借用；嵌套关闭消息拿不到状态，误走默认销毁流程。窗口被销毁后，退出消息同样没被正确处理，留下一个占用单实例锁的无窗口进程。

这会同时造成托盘入口失效、再次运行 EXE 无法打开设置，以及新版本被旧进程拦住。此前仅直接发送关闭消息的测试没有覆盖标题栏的真实路径。

## 修复

- 默认系统消息处理不再持有界面状态借用；标题栏关闭会保留窗口并隐藏到托盘。
- 重复启动使用有超时的窗口唤起，恢复最小化状态。若无法找到或唤起旧窗口，显示明确错误，不再直接无提示退出。
- 对单实例锁已建立但窗口尚未创建的启动间隙，进行最多两秒的等待，避免快速双击造成请求丢失。
- 托盘修改失败会尝试重新添加，添加失败也会尝试更新已有图标。可用标记以本次结果为准，不沿用旧的成功状态。
- 托盘不可用时显示完整设置窗口；关闭按钮不会把程序隐藏到一个不可访问的状态。
- 使用绿色 R 图标。单击、双击均可打开设置；设置窗口增加“退出程序”，无需依赖托盘退出。

Windows 仍可能把托盘图标收进任务栏的“显示隐藏图标”区域，程序不会擅自修改系统的图标显示偏好。即使图标被折叠，再次运行 EXE 也能打开设置。

## 验证

- 28 项自动化测试通过，严格 Clippy 检查通过，发布编译通过。
- 原生窗口回归测试覆盖真实的标题栏系统关闭消息、重入时的打开请求、托盘失败时保留可用窗口、托盘可用时隐藏、最小化恢复和直接退出。
- 托盘测试覆盖更新失败后重新添加、重新添加失败但已有图标可更新，以及两者都失败的情况。
- 真实 UI 操作：点击标题栏关闭，确认窗口隐藏；再次运行同一只读预览，原进程保留、原窗口重新出现，第二个实例退出码为 0，进程数量仍为 1。
- 真实 UI 操作：点击窗口内“退出程序”，确认测试进程完全结束。
- 本机的无窗口 0.1.0 残留进程已在核对路径和文件哈希后结束，从固定目录启动正式版 0.1.2，确认设置窗口可见且响应正常，最终只有一个 Replay Guardian 进程运行。原配置未修改。
- 测试没有修改配置、自启或 NVIDIA 状态。没有为验证托盘恢复而强行重启用户的 Explorer。

## 使用

请先解压到固定文件夹，再运行 EXE，不要长期从压缩软件的临时目录运行。若旧版已留下无窗口进程，可以在任务管理器中结束 `ReplayGuardian.exe` 后运行修正版；不要结束 NVIDIA 进程。

配置路径不变，原设置继续使用。更换 EXE 路径后，如果之前启用了自启，请在新版设置中关闭再开启自启，以更新路径。

0.1.0 的十分钟资源采样属于历史数据，本次没有重新进行资源长测。
