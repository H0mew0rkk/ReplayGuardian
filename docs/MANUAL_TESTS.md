# 后续实机检查

以下项目尚未全部执行。测试中如希望回放保持关闭，先暂停监控。不要手动修改 NVIDIA 的状态注册表或提高 MCP 权限来让测试通过。

## 基本操作

1. 运行 EXE，确认托盘图标和设置窗口存在，状态与 NVIDIA Overlay 一致。
2. 关闭设置窗口，确认程序仍在托盘；双击图标重新打开设置。
3. 从托盘暂停监控，再在 NVIDIA 中关闭回放，确认程序不会重新开启；恢复监控后，在录制允许的情况下确认恢复。
4. 再次运行同一个 EXE，确认只打开已有设置，不出现第二个常驻实例。
5. 从托盘退出，确认进程消失。网络请求进行中可能需要等待当前请求结束。

## 状态来源与恢复

1. 自动模式下确认实际方式是 MCP。关闭 NVIDIA MCP 后应先出现未知，连续失败后只在注册表已经校验的前提下回退。未校验时应保持未知，不发送快捷键。
2. 显式选择 MCP，接口不可用时不应静默换成注册表。
3. 按“校验注册表”的提示记录开、关、开；确认校验期间自动恢复停止。完成后分别测试事件和轮询模式。
4. 暂停监控并退出 NVIDIA Overlay，确认旧注册表值不能导致自动恢复；重新启动后再检查。
5. 恢复请求后立刻修改设置或暂停再恢复，确认没有因为清除冷却而重复发送操作。
6. 备用快捷键必须和 NVIDIA 设置一致。测试成功时确认状态真正开启，不能只根据按键动画或请求消息判断。
7. 自行正常播放受保护内容，观察 NVIDIA 的关闭行为；结束播放后观察恢复。若仍受限制，应等待并退避，不能关闭保护功能或连续强制输入。

## 通知、自启和兼容性

1. 通知默认关闭，正常启动和重复检测到开启均不应发出成功通知。
2. 开启通知，在程序实际恢复且确认开启后检查一次通知。恢复失败时不得通知。Windows 勿扰设置可能抑制展示。
3. 开启自启，注销后登录，确认程序在托盘运行；关闭自启后再次登录，确认没有自动启动。
4. 测试 Explorer 重启、睡眠唤醒和 NVIDIA App 更新。安装文件发生变化后，原注册表校验应失效。
5. 在另一台 Windows 10/11 以及不同 DPI 环境测试。分别记录系统 build、NVIDIA 版本、检测方式、是否成功和日志，不以本机结果代替跨系统结果。

资源检查可运行 `scripts/measure.ps1`。需要分别测量设置从未打开、设置打开、注册表和桥接模式；不要把一种模式的结果当作所有模式的结果。
